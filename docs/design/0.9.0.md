# Reiny 0.9 migration

Version 0.9 separates binary-owned app contracts from instance-owned config
assets. Runtime manifests, managed bindings and compiled reports remain version 2.
Existing named endpoint contracts, topic keys and wire schema fingerprints are
unchanged.

## Caller config assets

Keep `run`, `in` and `out` contracts beside the binary. A deployment selects that
app and supplies wiring and instance data:

```yaml
version: 2
modules:
  controller:
    source: ../../crates/nodes/hs-controller/profiles/policy-sim
    config: controller.yaml
    config_assets:
      - robot.yaml
      - model/robot.urdf
      - model/body.obj
      - policy.yaml
      - policy.onnx
    in:
      tick_world_state:
        from: [physics.world_state]
```

The call's `config` is relative to the calling manifest. Each `config_assets`
path is relative to the selected config's directory, not the calling manifest or
the app directory. The list names files; include referenced meshes, nested
configs and model files required by the app.

Omitting `config_assets` preserves the app's `run.config_assets`. Supplying a
list replaces it rather than appending. Supplying `[]` explicitly clears it.
Preparation freezes the effective list and preserves config-relative placement
when the deployment is relocated.

## Rust API and CLI

`ModuleCall` has a new public field:

```rust
config_assets: Option<Vec<std::path::PathBuf>>
```

Add `config_assets: None` to existing Rust struct literals to retain defaults.
Use `Some(Vec::new())` to clear them or `Some(paths)` for instance assets.
This public-struct change requires the 0.9 minor release.

Update workspace dependency requirements to `0.9.0` and install the matching CLI:

```sh
cargo install reiny-cli --version 0.9.0 --locked
```

Version 0.8 callers that do not use instance asset overrides remain valid version
2 manifests. Version 0.8 parsers reject the new call field; use the 0.9 CLI/parser
for deployments that need it.
