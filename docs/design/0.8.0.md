# Reiny 0.8: app-owned manifests

Manifest and managed runtime contracts use version 2. Version 1 contracts are
not silently upgraded; rebuild managed binaries and migrate their definitions.
The separate Git acquisition `lock.yaml` format remains version 1.

## Migration

1. Set `version: 2` in runtime definitions and schema catalogs.
2. Keep each app's `in`, `out`, `run`, `build`, and endpoint policies in its own
   `main.yaml`. Reuse that definition through `source` instead of copying it
   into every project.
3. Reduce caller inputs to explicit wiring, for example
   `ping: { from: ping.ping }`. Optional caller types are assertions, not
   definitions. Remove repeated caller `out` entries: all child outputs are
   visible. Composite exported aliases can use only `from`.
4. Put per-instance `config` and `args` on executable calls. Config paths are
   caller-relative; argument lists replace app defaults. Composite calls cannot
   override descendant configuration.
5. Declare stream policies in the app: output `qos` and `retention`, input
   `replay` and `buffer`. Use explicit source lists only for stream fan-in,
   without duplicate sources.
6. Declare RPC endpoints with `kind: rpc`, request `type`, and `response`.
   Both compiled descriptors are checked. Use one source per RPC input.
7. Use `run.kind: task` for finite work; the default `service` treats natural
   exit as failure. Both kinds must announce readiness.
8. Declare any host-owned child endpoint subsets under `owned_children`, using
   `inputs` and `outputs` lists. Ownership is exclusive. Child process runtime
   identity differs from the host endpoint source identity.
9. List helper binary names under `run.companions` (without `.exe`). List
   configuration files under `run.config_assets`, relative to the selected
   config origin. Caller config overrides change that origin. Explicit `../`
   assets retain their relative tree shape; absolute asset paths are rejected.
   Preparation freezes and fingerprints the config, assets, host, companions,
   and runtime libraries.

Managed code opens named endpoints before `cloudy.ready()`. Manifest policies
are the effective contracts; Rust types and compiled schema fingerprints prove
that each opened endpoint implements them. Caller wiring cannot change an
app's queue, replay, QoS, retention, or RPC behavior.

Standalone programs may continue using raw type-based publication, subscription,
RPC, and link APIs. A v2 build-time schema catalog alone does not request
managed graph behavior.

See [Modules and main.yaml](../modules.md) for the complete field guide and
[ping-pong-relay](../../examples/ping-pong-relay/README.md) for the reusable app
and project layout. Its Rust packages stay in place, preserving schema catalog
discovery and relative protobuf imports.
